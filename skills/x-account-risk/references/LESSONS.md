# X 账号抓取 + 评分 — 踩坑经验（实测于 2026-07-25）

## 1. GraphQL API 走不通，直接上 DOM
- 现象：带 cookie 访问 `x.com/<handle>` 首页能加载（登录态有效，返回 271KB logged-in 页面），但调 GraphQL `UserTweets` 接口始终 **401 Unauthorized**。
- 根因：X 对第三方/脚本登录态的 GraphQL 调用做了拦截（页面能看 ≠ API 能调）。`X-Twitter-Active-User`、`X-Csrf-Token` 等头补齐后仍然 401。
- 结论：**放弃 GraphQL，改 Playwright 真实浏览器 DOM 提取**。已验证稳定抓到真实推文。

## 2. queryId 位置已迁移（仅供排查参考，不推荐走 GraphQL）
- 旧路径 `responsive-web/client-web-*.js` 已失效，现位于 `x-web/x-web/entry-client-logged-out-*.js`。
- 初始加载的 vendor/main/zh 三个 JS **不含** queryId；要从 `main.js` 内搜 `operationName:"UserTweets"` 提取 `queryId:"RIylB10EGWyBSs4ZXpQjCw"`。
- 即便拿到也对 API 调用无用（见第 1 条），仅记录供未来 X 前端结构变化时参考。

## 3. 中文 X 的 profile 解析坑（已导致虚扣分）
- 中文界面用「**关注者**」而非「粉丝」。`Following` 对应「正在关注」。
- 错误正则：`Followers|粉丝` → `followers` 匹配不到变成 0，`following` 被「603 关注者」覆盖成 603。
- 后果：`_account_environment_score` 里 `followers<100` 判定成立 → 账号环境维度虚扣 3 分。
- 修复正则：`关注者|Followers|粉丝`（followers）与 `正在关注|Following`（following）。

## 4. 无限滚动丢数据（关键）
- 现象：滚动后 DOM 里 `article[data-testid="tweet"]` 计数从 14 掉回 5（X 卸载视口外节点）。最后一次性 `querySelectorAll` 只能拿视口内。
- 修复：**滚动时增量去重收集**（`Map` 以 `time|text[:50]` 为 key），停止条件 `连续 5 次无新增`。
- 实测 @Maibao1998：单次提取只 5 条，增量收集拿到 **31 条**。

## 5. 敏感媒体被折叠导致漏判
- 未点击「显示敏感内容」时，被折叠推文的 `img` 不在 DOM → `hasMedia` 误判 false → 漏扣「成人内容未标记 Sensitive Media」。
- 修复：提取每条推文时，先找文字含「显示/查看/可能包含敏感」的按钮并 `.click()` 展开，再判断 `hasMedia`。

## 6. 评分引擎入参适配要点
- 含媒体的推文：在 `raw` 字段追加 ` https://x.com/media_item`，供 `_content_marking_score` 判定「成人内容+媒体 → 需标记」。
- 维度字段名是 `risk_score` / `max_risk`（风险分逻辑，分数越高风险越大），不是旧的 `score` / `max_score`。
- 颜色映射同步反转：高风险红 / 中等橙 / 低绿。

## 7. 邮件发送（QQ 邮箱 MCP）
- `alias_id` 传**字符串**（非对象）；`to` 传**数组** `[{email,name}]`。
- 正文不要重复粘贴导致请求超长（曾因此触发输出截断/异常）。
- 阈值：正式监控账号 ≥60 分才发邮件；临时测试账号不发。

## 8. Cookie 有效期
- Cookie-Editor 导出的 `expirationDate` 是 Unix 秒。本地未过期 ≠ 服务端未吊销。
- 抓取脚本内置登录墙检测：若页面出现「登录/Sign in」且 tweet 数为 0 → exit 3，需用户重新导出 cookies。
- 读公开推文只需任意一个有效登录态（可用其他账号的 cookie），不需要目标账号自己的 cookie。

## 9. 个人资料级敏感警告门（2026-08-01 新增，重要）
- 被 X 标记为敏感的账号，主页会显示「警告：此个人资料可能包含潜在的敏感内容」+「是，查看个人资料」按钮
  （`button[data-testid="empty_state_button_text"]`），不点击则 `article` 为 0、profile 全空，抓取“看似成功实则为空”。
- 实测 @zixuanmiao、@dangao0709 都有此门；@kokona5201314 等没有。⚠️ 该门本身就是“X 已将该账号标记为敏感”的风险证据，应记录进报告。
- 修复：用 `page.locator('button[data-testid="empty_state_button_text"]').click({timeout: 25000})` 自动等待点击，失败再按文本匹配 `button/div[role=button]/a`。

## 10. 转帖识别（2026-08-01 新增，重要）
- “已转帖/Reposted”横幅**不在正文 `div[lang]` 里**，正则匹配正文开头无效。
- 可靠规则：**主时间线（profile 主页 tab）出现的文章全部属于本账号**；文章作者 != 本账号 = 本账号的转帖（X 主时间线只展示自己的帖子和转帖）。
- 回复标签页（/with_replies）会混入对话对方推文，只保留作者 == 本账号的。
- 实测 @dangao0709 主时间线 240 条中 195 条是转帖（63% 搬运号），漏识别会导致“原创/搬运比”与 NSFW 统计严重失真。
- 注意 handle 大小写：URL 作者统一小写比较，`Leon_Saki_d` 这类混合大小写句柄必须 `.lower()` 后再比。

## 11. 媒体检测（2026-08-01 新增）
- `img[data-testid="tweetPhoto"]` 会漏判（懒加载/图集），且 `img[src*="pbs.twimg.com"]` 会把**头像**误判为媒体（实测全部文章 hasMedia=true 的假象）。
- 正确选择器：`div[data-testid="tweetPhoto"], div[data-testid="tweetVideo"], video, img[src*="pbs.twimg.com/media/"], img[src*="ext_tw_video"]`。
- 校准：检测出的媒体数应与 fxTwitter `media_count` 基本一致。

## 12. 互动数字解析（2026-08-01 新增）
- X 把「回复、转帖、赞、书签、阅读」合并放在一个 aria-label（如“23 回复、61 次转帖、1921 喜欢、309 书签、400258 次观看”）。
- 原实现取第一个数字 = 回复数，会把点赞数算错。必须按关键字分别提取：`([\d,]+)\s*喜欢 / 次转帖 / 回复 / 次观看 / 书签`。

## 13. Tier 1 严重违规必须语境化（2026-08-01 新增，重要）
- 成人圈常用词大量误报：`萝莉/正太`（风格标签）、`cp`（CP 粉用语）、`强迫`（角色扮演）、`强奸`（“被玩具强奸了”）、`下药`（“蛋糕别下药”自嘲梗）、`未成年`（“七个未成年女友是吧”调侃）。
- 处理：灰色词移入 Tier 2 并提示人工复核；`强奸` 需与 迷奸/诱奸/轮奸/未成年/非自愿 等共现；`下药/迷药` 需与 强奸/昏迷/灌醉 等共现；`未成年` 需与性语境共现。
- 误报后果：一条 +20 的 Tier 1 会让 30 分账号跳到 50 分，必须先查 `tier1_details` 再定案。

## 14. 小号公平性（2026-08-01 新增）
- “>70% 推文点赞 <5”惩罚对 <5000 粉小号是正常现象（740 粉账号均赞 2-3 属常态），会造成结构性误伤（实测 33→22 分）。
- 修复：低互动惩罚仅适用于粉丝 ≥5000 的账号。

## 15. ACC 维度避免双重计分（2026-08-01 新增）
- 漏标媒体已由“标记合规”维度扣分；ACC 维度只应按**主时间线成人/敏感占比 >20%** 判定是否成人内容账号，否则同一批漏标被扣两次。

## 16. 短英文关键词词边界（2026-08-01 新增）
- `ts`/`cp`/`sub`/`18+` 等纯 ASCII 短词子串匹配会命中任意文本（如 “posts” 含 ts）；必须用 `(?<![a-z0-9])kw(?![a-z0-9])` 词边界。

## 17. 搜索可见性实测（2026-08-01 新增）
- 三项测试：自动补全（是否出现“前往 @handle”）、用户搜索（精确真号是否在结果中）、`from:` 推文搜索（是否有结果）。
- ⚠️ `from:` 零结果**不能直接判定 shadowban**：查看者“隐藏敏感内容”设置会让所有敏感账号 from: 为空（实测对照组 from:jiuxingmao / from:zixuanmiaob 同样为空）。
- 用户搜索/自动补全都无精确真号（相似号占据结果）→ 记 +4；自动补全有直达入口或 from: 有结果 → 可搜索，不扣分。
- 仿冒号常见（zixuanmiaoX/b/55/s、kokona520131455、dangao070977），写入 `search_evidence.json` 的 `impersonators` 字段并在报告提示。

## 18. v4.2 第 10 维度：账号存续风险（2026-08-01 新增）
- **背景**：合规分低 ≠ 不会被封。实测 10 个账号中多个是“复活号”（简介写“复活版/重生号/原3万粉丝账号被冻，这是新号”），按原运营模式继续发招嫖/露骨内容，再封概率极高。
- 新维度信号：封禁/重生史（复活版/重生号/被冻/冻结/重开/復活/旧号/被盗号/号被盗）+4/个（上限 8）；性交易商业信号（接线下/可约/全国可飞/莞式/报价/课表/口令/好友位/私信解锁/涩涩基地/包夜/线上一对一/领课表/接单/约炮）+3/个（上限 7）；隐私开盒（地址是/家庭住址/住址）+5。
- **误报教训**：宽泛词必须排除——“封号/被封”会命中“QQ 被封号了”（与 X 无关），“援交”会命中“没有援交到的一天”自嘲梗，“新号/线下/约吗”过于宽泛；转帖内容是别人的话，一律不算账号自述。
- 检测范围：简介 + 本账号原创/回复（is_retweet=False）。
- 效果：复活号/招嫖号普遍升入中风险（30-41），干净个人号保持最低分（栗子 19），警戒作用显著提升。

## 19. v4.3：商业变现信号（2026-08-01 新增）
- **背景**：第 10 维度只抓“性交易”信号，漏掉了简介里明显的变现词——实测 @wuuuuuucy 简介“🚪门槛300私聊🉑线下”一个都没命中（只靠“约炮”玩笑 +3）。
- 新增变现词：门槛/可线下/🉑线下/付费/有偿/包月/订阅/打赏/图包/电报/加群/淘宝/店铺/发售，与性交易信号合并计分（+3/个，上限 7）。
- **否定声明排除**：“无图包/不约炮/不可约”等声明不扣分（实测 @zixuanmiao 简介“无推广、无图包”）。
- **“门槛”需带数字**：“门槛300”算，“门槛是什么”（圈内术语提问）不算（实测 @cuqngyu143776 误报）。
- 效果：@wuuuuuucy 38→41（门槛300/可线下/电报），@dangao0709 32→35，@kokona 41→43；干净号保持低分。

## 20. v4.4：真人感/营销号形态（2026-08-01 新增）
- **背景**：存活 7.5 年、21.7 万粉的 @wuuuuuucy 与大量短命号的差异在于“像真人博主”——有人设、生活内容、有节制的变现；纯营销号（卖货+无生活+搬运）最易被封被举报。
- 新维度信号：卖货词推文占比 >=25% +3 / >=50% +6；简介卖货词 >=2 +3；强生活词占比 <8% +3；转帖 >50% +3；生活化 >=25% -2 / >=50% -4。
- **误报教训**：“今天/日常/分享”等宽泛词会命中广告文案（实测 @Conny_vv 纯广告号生活感虚高到 60%），必须用强生活词（吃饭/上课/上班/考试/朋友/天气/喝酒等）。
- **bio 盲区**：只统计推文会漏掉“简介卖货”的号（@kaixintangtang/@Conny_vv 推文无卖货词但简介全是口令/课表），需叠加简介卖货词检查。
- 效果：营销号形态 6-9 分的号（@xieshujingvlog/@ShiChengJiangYa/@ChapelJune5222 等）全部进入中风险；真人感号（@wuuuuuucy 39、栗子 18）保持区分度。

## 21. v4.5：变现词分级（2026-08-01 新增）
- **原则**：露骨变现（明码标价/直接招嫖）必须扣分；隐晦引流（可辩解的联系方式）不扣分仅提示。
- A 级（必扣 +3/个）：接线下/可约/全国可飞/莞式/报价/课表/口令/好友位/私信解锁/涩涩基地/包夜/线上一对一/接单/约炮/门槛(带数字)/付费/有偿/包月/订阅/打赏/图包/淘宝/店铺/发售/卖淫/嫖/下单
- B 级（0 分，仅提示）：电报/tg/加群/私信/找我/加我/解锁/可线下/🉑线下/购买/价格
- **误报教训**：“购买/价格”是日常词（栗子“拼多多买衣服”被误判 +3），必须降级；B 级检测需排除已被 A 级覆盖的子串（“私信解锁”命中后不再提示“私信”）。
- 效果：@wuuuuuucy 39→37（电报/可线下降级为提示）、@kaixintangtang 35→32（电报不再扣）、栗子回到 18；@dangao0709 38（原创内容露骨词增多）。

## 23. v4.7：置信度 / 校准 / 分级 / 治理（2026-08-01 新增）
- **置信度公式**：`100 - 未验证维度×6 - max(0, (1-覆盖率)×50)`，clamp 30-95；分数区间 ±10。实测 @lengmei111（覆盖率 7.8%）置信度 42%，@Conny_vv（覆盖率 95%）置信度 86%——覆盖率低的号不再假装确定。
- **校准教训（160 样本队列）**：用户关注列表 160 个同类账号全部存活（0 死亡）——关注列表不是死亡样本池；简介露骨变现组（41 个）与无变现组（85 个）中位存续年限均为 4 年，变现信号对“存续”无区分力 → 变现上限 7→5。
- **Tier2 分级**：3 条和 160 条同扣 10 分的信息丢失问题修复（3-9 +10 / 10-49 +15 / ≥50 +20）。
- **marking 平台尺度**：Sunny（平台标记率 0.7%）漏标扣分 50% 折算并注明“平台认可的擦边尺度”；平台标记率 ≥10% 的账号（如 dangao 整改后 1%）也受益——整改删帖后标记率会下降，避免双重惩罚。
- **回归基线**：golden_set.json 固化 15 账号分数；历史趋势存 data/history/<handle>.jsonl，报告显示上次→本次变化。
- **遗留**：P0 语义复核层（LLM 判语境）需 API key，当前以“待人工复核清单”替代；分页抓取受 X 无限滚动限制，大号覆盖率低时置信度自动降低。

## 24. v4.8：第二轮校准修正（2026-08-01 新增）
- **死亡样本来源（验证集 v1）**：从 160 个关注账号的 bio 中提取“旧号/被封/重生”表述与 @提及，批量探测出 5 个死号（@mozidoum 等）+ 12 个重生史账号 = 17 个正样本（validation_set_v1.json）。
- **11 vs 149 对比的关键修正**：
  1. 重生史组注册年限中位 1 年 vs 4 年 → 新增“新号(注册<1年、无认证) +2”
  2. 重生史组 bio 露骨变现 55% vs 23% → **变现权重恢复 5→7**（v4.7 用“存活年限无差异”降权是错误口径——该口径无法区分“活着的变现号”和“被封过的变现号”）
  3. 封禁词表召回仅 27%（3/11），扩展模式“大号被封/老号被封/账号被封/号被封了/秽土转生/转生”召回 55% 且误报 1% → 恢复精确模式词
  4. 蓝标无差异 → 信任加分保留
- **方法论教训**：校准必须用“是否被封过（重生史）”做标签，不能用“当前是否存活”——存活样本内的特征对比有幸存者偏差（v4.7 的错误来源）。

## 25. v4.9：train/test 校准证实过拟合 + 复核落盘（2026-08-01 新增）
- **数据集扩充**：用户关注列表中最爱关注的账号 @cdmxiaoxi（6756 关注）实际只能加载 73 个——X 对 following 页面限制约 50-70 个/账号，与关注总数无关；合并 4 个来源去重得 335 个，再加 bio 提及探测 33 个 = 358 样本（validation_set_v2.json）。
- **过拟合实锤**：70/30 划分后训练 AUC 0.821 / 测试 AUC 0.560——v4.8 在 11 vs 149 上调整的权重（新号+2、变现 7）测试集上几乎随机，全部回退（新号信号移除、变现回 5）。教训：**任何权重调整必须有独立测试集验证，否则只是记忆训练集**。
